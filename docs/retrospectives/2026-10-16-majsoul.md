# 2026-10-16 雀魂插件排查复盘

> 这是当时的原始记录，保留结论与原貌。插件后来已被移除，`data/MajsoulUID` 只剩残留。
> 它记录的不是「修好了什么」，而是「怎么判断一个东西值不值得继续修」。

## 一句话结论

插件本身没坏，是**上游两次改版**把它打挂了：雀魂官方换了登录流程（插件拿不到 token），牌谱屋加了反爬门禁（插件拉不到数据）。我们把「插件为什么悄悄失败」查清并修好了，剩下的取决于要不要投入。

## 干了啥（按时间线）

1. **分析「添加账号后登录报数据库为空」**
   查清链路：添加账号 → 雀魂官方 WS 登录 → 写 `MajsUser.cookie`；启动推送 → `get_all_user()` 读库 → 建连。
2. **实施 P0 + P1 本地修复**（不提交、不部署）
   - 登录：`manual_login` 补三道校验（error.code / account_id / token 空值），空 token 不许写库、不许假装成功
   - 账号池：`start()` 空 cookie 短路走账密、单账号失败跳过不阻塞、修掉空池 IndexError
   - 订阅：观战订阅按 `(uuid, user_id)` 去重（修「只通知第一人」+「结束消息从不发送」）
   - 新增「取消雀魂观战订阅」命令 + 帮助条目
   - 「删除 uid」联动清理推送与观战订阅残留
   - 多 bot 重复推送收敛
3. **补日志**（`[majs]` 前缀）
   登录链路、账号池、好友上下线/开局/终局、牌谱拉取失败——关键节点全部可观测。
4. **给仓库的 Agent skill 文档补了 3 条踩坑记录**
5. **日志上断点后发现真凶：`error.code=151`**
   查社区 → 雀魂 2026 年 5 月上线 Unity/WebAssembly 新网页端，`Lobby.login` 账密 RPC 被服务端关闭，官方改走 UStar + oauth2。上游插件作者最后实质提交停在 8 月，**等他修不现实**。
6. **评估三条出路，选定路线 A（牌谱屋轮询）**
   A 牌谱屋轮询（零登录、零维护）／B 浏览器自动化（需 Chromium + 长期维护）／C 转国际服（直接否掉，看不到国服玩家）。
7. **写了延迟观测脚本并修了低版本 Python 兼容问题**
8. **第二次打击：牌谱屋 `player_records` 被反爬拦截**
   - 顺手揪出插件的一个真 bug：拦截返回 dict 被当成 list，`record[::-1]` 炸出 `KeyError: slice(None, None, -1)`——原来原作者把异常吞成了正常返回值
   - 本地修好 `request.py`：加浏览器请求头、非 200 记日志、dict 响应不再透传崩溃
9. **查到社区标准答案**
   另一个雀魂插件（Yunzai 版）FAQ 明确写：牌谱屋 API 现在需要 **Bearer token**，需联系作者 SAPikachu 获取。**没有任何社区项目是靠绕过解决的。**
10. **止损决定**：规模不大、投入不划算 → 清理临时文件，收工。

## 关键技术结论（以后有用）

| 事项 | 结论 |
| --- | --- |
| 账号池为什么「数据库为空」 | 不是数据库有问题，是没拿到 `access_token`，`get_all_user()` 过滤掉了 cookie 为空的行 |
| 为什么拿不到 token | 旧式 `Lobby.login` 被服务端关闭（151），官方改走 UStar + oauth2 |
| 雀魂登录是不是彻底死了 | **不是死，是换了流程**。牌谱屋作者自己的爬虫脚本 7 月有 "New login flow" 提交佐证 |
| 牌谱屋是不是封死了 | 不是，是需要 Bearer token（联系作者即可），报错原文就这么写的 |
| 自动解 Cap 工作量证明 | 技术可行，但绕过作者明确设置的反爬门槛，不建议 |
| 第三方本地登录程序是什么 | 协议登录守护进程（不是浏览器），直连服务端 WebSocket + protobuf，本机 127.0.0.1 暴露 HTTP 接口 |
